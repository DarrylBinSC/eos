## 1. The problem this solves

Both forums run free-form. The consequence is not that the hour is wasted; it is that items raised in them do not survive the week. There is no carried record, so an issue raised in one session is only present in the next if someone happens to remember it. Repetition then substitutes for progress: the same topic recurs for weeks and nobody can tell whether it moved, because nothing recorded where it stood last time.

The corroborating evidence is in the operating record. The truncated manufacturer part number defect has been live since at least 08-12 with no named owner. The WMX complex-build questions have been open since 07-17. The Federal Reserve release hold was evidenced on 08-27 and again on 08-31 in identical terms. Each of these has been discussed in one of these two forums more than once. None of them has a date attached to a named individual.

The second consequence is evidentiary. The 2026-09-01 weekly briefing lists nine meetings "not transcribed at source," and every one is a forum Darryl owns or attends by choice. Coverage is strongest where Darryl has least control and weakest where he has most.

**What actually stops things dropping is not a better weekly agenda. It is a register that carries forward.** A fresh agenda each week is a new sheet of paper; last week's items are only on it if someone re-types them. Section 3 is the core of this standard for that reason.

## 3. The rolling agenda register

One file per forum, updated in place every week. Not a new file per session, because a new file per session is exactly the mechanism that drops items.

Each item carries: an ID, the date it was raised, one named individual as owner, the next step, a date, current status, and weeks open.

### The rules that make it work

1. **Items leave only by explicit close.** A close requires a date and a one-line resolution written into the register. Nothing is removed because it went quiet, and nothing is removed because it was not discussed.
2. **Carry-forward is automatic and visible.** The full register is published with every agenda, not summarized. An item that has not moved appears every week showing that it has not moved.
3. **One named individual per item, never a team and never a role.** "The EUDM team" is not an owner. If no individual can be named, that fact is the item.
4. **Aging forces disposition at four weeks.** Any item at four weeks or more with no movement is disposed of at that session: escalated with a named recipient, re-dated with a stated reason, delegated to a different named individual, or killed. Continuing unchanged is not an available option. Darryl makes the call.
5. **Nothing becomes an item unless it is read back.** Items enter the register only through the closing readback, or by Darryl adding them between sessions. This matters as much as the carry-forward rule: without it, the register bloats with everything anyone mentioned, and a register nobody trusts gets ignored, which returns the forum to where it started.
6. **Active items capped at twelve per forum.** Overflow moves to a Parked section, annotated with the date and reason, never deleted. Same discipline as the caps on `03` and `04`.
7. **The register reconciles to the EOS living documents weekly.** The forum register is the working surface; `05_Commitments.md` and `03_Decision_Log.md` remain the system of record. Section 4 sets out how, and in which direction.

## 4. Reconciliation to the EOS living documents

The forum register and `05_Commitments.md` will overlap, and the overlap has to be governed or two lists drift apart and neither is trusted. The model is deliberately asymmetric.

### 4a. Direction of authority

**Downward is mandatory.** Every open item in `05` or `03` routed to one of these forums appears on that forum's register. If an item is being tracked as belonging to this forum, the forum sees it every week. No exceptions, because a commitment routed to a forum that never discusses it is the original failure this standard exists to fix.

**Upward is conditional.** A forum register item enters `05` only if it passes the attribution test already in the operating manual: Darryl's own words, his confirmation, or follow-through on a decision he owns with no other executor named. Items raised in a meeting he attended do not qualify automatically.

This asymmetry is the point. Without it, thirteen forum items become thirteen Register A entries inside a month, Register A blows its cap of fifteen on meeting minutes, and the July redefinition that pulled standing duties out of the register gets undone. Most forum items should live on the forum register and nowhere else. That is not a gap.

### 4b. Where an item belongs

| Situation | Home |
|---|---|
| Darryl takes the next step, and it passes attribution | `05` Register A, cross-referenced on the forum register |
| His organization owns it, named executor, he engages at a gate | `05` Register B |
| Owed to him by someone else, chased on cadence | `05` Register C |
| A choice with options that needs to be made | `03` Decision Radar or Backlog, with this forum named as the route |
| A risk being tracked but not currently actionable | `04` Watch List |
| Real work owned by a named person, no Darryl next step, no decision pending | Forum register only |

The `EOS ref` column on each register carries the answer. Four values are valid, and the fourth is the one that does the work:

- A live ID (`05` A29, `03` Decision Backlog) means the item is reconciled.
- `04` Active means it is a tracked risk with no commitment attached.
- Forum only means it is deliberately not in the EOS registers.
- Candidate A or candidate B means the item probably should be in `05` and is not yet. These are the reconciliation queue, and they are the reason to run section 4c.

As seeded on 2026-09-01, eight of twenty-three items across both forums carry a candidate flag. That is the current gap between what the forums are carrying and what the registers know about.

### 4c. The weekly reconciliation

Runs in a Cowork session with this folder open, after the forum summary is posted and before the next register is published. Five steps:

1. Read the meeting summary. Update status, dates and the weeks-open count on the register.
2. Close anything closed, into Part 4, with a date and a one-line resolution.
3. Push upward: for each item flagged candidate, apply the attribution test and either create the `05` or `03` entry and replace the flag with the new ID, or change the flag to Forum only with a reason. A candidate flag surviving three weeks is itself a disposition item.
4. Pull downward: check `05` and `03` for anything newly routed to this forum and add it.
5. Report divergences rather than silently resolving them: an item closed in `05` but still open on the register, an owner who differs between the two, a date that moved in one place and not the other.

Step 5 matters most. Silent reconciliation produces a tidy pair of files and hides the fact that two records disagreed, which is exactly the information worth having.

### 4d. What this is not

The forum register does not replace the weekly briefing, and it is not a status report. It holds open items for one forum. Portfolio-level judgment stays in the briefing, risk stays in `04`, and the decision trail stays in `03`.

### 4e. Running it from a session

Say any of these in a Cowork session with this folder open. Each maps to a defined action rather than a general request, so the output is repeatable.

| Say | What happens |
|---|---|
| "Reconcile the WAM register" (or entroCIM) | Section 4c, all five steps, ending with the divergence report. |
| "Publish the WAM register for Monday" | Reconciliation, then the three decisions selected and written for the coming session, ready to paste into the chat. |
| "Update the register from this summary" plus the pasted summary | Steps 1 and 2 only. Use when the meeting has just happened and there is no time for the full pass. |
| "What is aged on both registers" | Every item at four weeks or more with no movement, with a recommended disposition for each. |
| "Add to the WAM register: ..." | A new item, with owner, next step and date, and the attribution test applied to decide whether it also goes into `05`. |
| "Close W5" plus the resolution | Moves the item to Part 4 with a date, and reconciles the matching `05` entry. |

The registers are plain markdown and can be edited by hand at any time. Nothing in the process depends on going through a session.

## 5. The session structure

Two rules do most of the work.

**Decisions first, status last.** Sessions that open with status never reach decisions, because status expands to fill the hour and the hard items arrive when everyone is tired.

**Nothing on the agenda that is only an update.** If an item does not need a decision, an escalation, or a judgment call, it is sent in writing beforehand and not read aloud.

Standard 60-minute shape:

| # | Block | Time | Content |
|---|---|---|---|
| 1 | Decisions required today | 15 min | Maximum three. Each stated as a question with options, a recommendation, and the person who decides. |
| 2 | Register walk | 15 min | Every active item, in order. One line each: moved, did not move, closed. Items aged four weeks or more get disposed of here. This block is the anti-drop mechanism and is not compressible. |
| 3 | New blockers and escalations | 10 min | What is stuck that is not already on the register. |
| 4 | People, capacity, messaging | 5 min | Staffing, load, role changes, and what goes to customers or executives this week. |
| 5 | Open floor | 10 min | Section 6. |
| 6 | Readback | 5 min | Chair reads back every decision and every new item with a named owner and a date. Nothing enters the register that is not read back here. |

For a 30-minute session: decisions 8, register walk 10, new blockers 5, open floor 4, readback 3. People and messaging move to the alternate week.

## 6. The unstructured segment

The candid part of these meetings is not a defect to engineer out. Both are the only weekly setting where leaders carrying the same portfolio speak without a customer, a peer organization, or a governance audience present. Several current watch-list items originated as exactly that kind of unstructured remark.

The failure is not that it happens. It is that it happens instead of the decisions, and that nothing is extracted from it.

Containment, not suppression:

1. A named slot, placed last. Unstructured discussion with a scheduled home stops colonizing the first forty minutes.
2. Time-boxed, extendable only by explicit agreement out loud.
3. Converted in the readback into one of three outcomes: a decision, a register item, or nothing. "Nothing" is a valid and frequent outcome and should be said aloud, so the room learns that raising something does not automatically create work.
4. Transcription pauses for this block if the room asks.

## 7. Transcription and summarization

**Teams transcription on, video recording off.**

Rationale. A transcript gives Copilot enough to produce a recap and gives the daily and weekly evidence packages a source, at a materially lower perceived cost than a recording. A recording is a rewatchable artifact of people's faces and tone, and that is what people object to. Recording adds fidelity these sessions do not need.

Mechanics:

1. The organizer starts transcription at the top and says why in one sentence. Not an apology.
2. The transcript feeds a Copilot recap.
3. The chair edits the recap before posting. Not optional. AI meeting notes misattribute speakers, and `CLAUDE.md` carries a documented instance of an entire meeting's remarks credited to the wrong person. Any consequential statement attributed to a named individual is verified before the summary goes out.
4. The edited summary goes into the meeting chat within 24 hours: decisions made, new register items with owner and date, items closed, items deferred with a reason.
5. Darryl updates the register from the summary before the next session.

**Dependencies to confirm, not assumed:**

- Tenant policy permits transcription for these organizers. Assumed available, since transcripts and Copilot recaps exist for other forums in the same tenant.
- Copilot post-meeting recap is licensed for the forum owner. Not confirmed.
- India-based attendees fall under the same tenant policy. Not confirmed.

If Copilot recap is unavailable, the fallback is the transcript plus a chair-written five-line summary. The written record is the requirement; transcription is the cheapest route to it, not the only one.

Teams announces transcription to all participants, so nobody is recorded unknowingly. If someone objects, that is one conversation held in the open, not a reason to run the forum unrecorded indefinitely.

## 9. How this gets judged

Reviewed at six sessions per forum, roughly 2026-10-20. Five countable measures:

1. Items closed with a recorded resolution. This is the measure that matters; the others are inputs to it.
2. Sessions with at least one decision recorded. Target: every session.
3. Items aged four weeks or more still carrying no disposition. Target: zero.
4. Sessions transcribed with a summary posted inside 24 hours. Target: all.
5. Register published 24 hours ahead. Target: all.
6. Items carrying a candidate flag for more than three weeks. Target: zero. This measures whether reconciliation is actually running.

If the format runs and measure 1 does not improve, the problem is not the agenda and the format should be dropped rather than defended. A structure that produces compliance without closures costs the same hour and hides the failure.

## 11. Forum coverage

Which forums can be run on this standard, and at what level. Source for cadence, owner and engagement level is `07_Operating_Cadence.md`.

Three levels of support:

- **Register** — a rolling agenda register maintained in `Deliverables/Portfolio_Admin/`, published ahead of each session, reconciled weekly. For recurring, decision-carrying forums where items must survive week to week.
- **Agenda** — a one-off structured agenda built on request for a single session. No carry-forward. Say "build an agenda for X".
- **Prep** — the existing capability: open decisions, commitments and stakeholder context routed to that forum. Say "prep me for X".
